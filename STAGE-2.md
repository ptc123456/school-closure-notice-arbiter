# Stage 2 — School Closure Notice Arbiter Implementation Specification

Storage: `TreeMap[str, ClosureCase]` with owner, school_id, url_a/url_b, closure_date, reopen_date, state, outcome, notice_revision_a/b, evidence_digest, retry_count:u8. API: `create_case`, `freeze_case`, `assess`, `retry_unresolved`, views. Validate distinct HTTPS sources and ISO `YYYY-MM-DD`; reject local time. Leader/validator compare school ID, closure/reopen dates, revision and outcome; raw reasoning is not compared. WRONG: use HTTP response timestamp as latest. CORRECT: use explicitly declared notice revision/effective date. Test reordered notices, date conflict, missing date, 404/429/disagreement, schema and Studio E2E.

Revision 2 adds a complete missing-field state table from Stage 1 and `revision_kind = ORDINAL|EFFECTIVE_DATE`. Mixed kinds, absent revisions, conflicting school IDs and undeclared unknown-duration markers yield `UNRESOLVED`. Recheck reordered URLs, conflicting HTTP timestamps, equal/missing revisions and every missing-field combination. Runtime probe covers ISO date normalization, storage record, bounded web result, serialization and disagreement before technical lock.
